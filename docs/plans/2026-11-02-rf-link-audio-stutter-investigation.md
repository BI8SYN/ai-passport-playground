# RF Link 卡顿诊断待办与无频谱UI建议

2026-11-02：用户认可先记录以下诊断方向，并询问关闭频谱后的UI安排。本文件为待办记录，不代表已经实现、烧录或定位根因。

## 已记录的三项诊断工作

1. 制作无频谱对照版本：停止FFT、分析采样窗口维护和频谱柱/峰值动态绘制；不只是隐藏控件。保留服务器、呼号、收发状态、距离和历史等业务信息。
2. 补齐接收诊断：单独记录BLE音频因状态锁竞争而未进入核心接收逻辑的丢帧，保留/核对已有播放underrun统计，并记录接收与播放节拍。需区分开机累计、当前流和正常停止后的排空，避免不同范围的计数混为丢包率。
3. 做同条件对照：保持同一App、ADPCM格式、20ms分帧、60ms起播、信用、网络和音量策略，比较频谱开启/关闭的听感、锁竞争丢帧、有效接收、欠载和节拍；不要同时修改音频参数以免混淆结论。

## 已知事实与判断边界

- 当前UI主循环约50ms刷新一次，音频新鲜时做256点浮点FFT、16频段log10f和频谱柱重绘。FFT在core锁外；采样窗口复制及界面业务快照仍短暂使用同一状态锁。
- hm_audio_receive使用非阻塞取锁，失败直接返回，尚无独立锁竞争丢帧计数；存在风险不等于已经证明当前卡顿来自该路径。
- refresh_ui在共享状态锁内还会格式化位置/距离和业务数据。因此仅停止FFT不保证消除全部锁竞争。
- 已有启动日志ui_max_us=66705覆盖整个界面更新路径，含等待/调度；当时未进行实际通话，不能把这个数当作FFT耗时或卡顿根因。
- 当前实机为仅ADPCM镜像77cb3a06/ELFa4a8bdc3。此次记录不打开串口、不复位、不修改固件。

## 无频谱UI建议（待用户确认）

建议小幅调整主屏，延续现有黑底荧光风格、主题、顶栏服务器/电量和大呼号，不直接留下原频谱占位。

| 状态 | 建议调整 |
| --- | --- |
| 收听 | 呼号保持主视觉；将现有距离/网格信息适度上移，给长呼号与辅助信息更多间距；上一位继续放底部，不重复显示 |
| 讲话 | 保留讲话状态；将现有计时移到呼号下方并放大，原位置不再重复计时；仅按秒更新，保留松开结束提示 |
| 守听 | 保持最近3位通话；按实际留白微调间距，无需增加新内容 |
| 等待/断连/故障 | 保留现有简短原因与操作提示，不保留装饰性频谱区域 |

不增加新的持续动画或高频电平显示作为替代。音量、配对管理、主题、完整历史及电台资料页无需因此重设计。UI提案尚未定稿，本轮不改正式v2设计基准或创建新的架构决定。
