# 0002：RF Link Passport 采用独立联网电台方向

**已被[ADR 0003：纯BLE手咪](0003-rf-link-ble-handmic.md)替代。以下保留当时决定，不作为首版当前方案。**

日期：2026-10-31。用户在iOS功能/协议梳理后明确选择“按passport独立的方向来”。

## 决定

- Passport通过自身Wi-Fi连接服务器，并承担实时语音收发、编解码、音频I/O及PTT；手机不作为常规音频/网络网关。
- 沿用已确认的外部代签原则：Passport不保存Ed25519业务私钥；每登记实例使用独立证书/密钥，不复用手机自己的业务身份。
- 不修改用户设备eFuse、不永久锁机；目前不以抵抗主动克隆为目标。

## 尚未决定

初始化配置、配网、证书申请及长期代签使用原生App BLE、Web或组合方式，仍在讨论。本决定不批准具体UI、首版全功能范围、证书恢复策略或实现排期。

## 后果与验证边界

BLE代签不承载持续音频。已有实验只证明公开测试身份下的代签/验签与绑定流程；Wi-Fi/BLE共存、C3实时codec、峰值内存、正式证书/SAS及完整RF Link互通仍需单独验证。工程风险不因方向确认而视为解决。

研究依据见[设计输入](../research/rf-link/passport-design-inputs.md)。
