# 音频诊断与锁竞争修复

此诊断保持format2、100字节、160采样/20ms、60ms起播、超过6帧修剪到3帧及32信用不变。它用于同条件频谱开关对照，主机测试通过不等于实际语音卡顿已解决。

`audio.stats`参数为`{"section":"rx"}`或`{"section":"playback"}`；沿用正式控制请求/响应封装，分别请求以保持512字节控制上限。仅在当前认证会话内查询。字段快照由同一core锁保护，开机计数另用短临界区复制，不等待音频任务。

接收结果字段：

| 字段 | 范围及解释 |
| --- | --- |
| `boot.queue_drop` | 本次启动累计，6帧音频入口队列满导致实际拒绝入队的帧数 |
| `boot.flow_coalesced` | 本次启动累计，新绝对信用覆盖尚未处理Flow的次数；不是音频丢帧 |
| `boot.stale` | 本次启动累计，排队超过120ms后丢弃的音频/Flow条目数 |
| `boot.rejected` | 本次启动累计，工作线程拒绝的条目，含代次、认证、sid、stream变化及核心协议/状态拒绝；不可直接算成链路丢包 |
| `boot.lock_waits` | 本次启动累计，工作线程即时取core锁失败而进入最多10ms等待的次数；持续竞争可重复计数，不是丢帧 |
| `queue_depth` | 此刻入口音频队列深度，0–6；不含正在处理帧或Flow槽 |
| `scope`、`sid`、`stream_id`、`active` | `latest_stream`表示当前会话最近一条流；`active=false`仍可看停止后该流数据。新流清零，重新建会话也清零；没有流时stream_id=0 |
| `accepted` | 最近流成功进入核心接收的帧数 |
| `queue_max_ms` | 最近流成功接收帧从BLE回调到达至工作线程取得core锁后处理的最大等待毫秒数；新流清零。被拒绝或过期帧不计入 |
| `gap_max_ms` | 最近流有效接收帧在BLE回调抵达时刻的最大相邻间隔；首帧不计算。排队工作线程的集中处理不改变该时间口径 |

播放结果具有同样`scope/sid/stream_id/active`：`slots`为该流实际请求播放槽次数，`gap_max_ms`为相邻槽处理的最大时间间隔，`write_max_us`为该流Codec写入调用最大耗时（包含等待/调度，并非纯CPU运算时间），`underrun`和`seq_missing`直接使用现有核心流统计。二者不是开机累计，停止前自然排空、等待流超时期间也可能计入欠载，不能据此单独判定网络丢包率。`spectrum_enabled`报告真实分析开关状态。

NimBLE音频与Flow回调不取core锁，仅检查长度、认证和连接代次后复制。音频入口最多6帧（120ms），Flow单槽覆盖并优先处理，维持绝对信用重复安全。工作线程在core锁外等待，获取锁后再次选择最新Flow或音频；再检查认证、连接代次、sid、stream及排队年龄，最后调用核心（先执行当前时刻超时检查）。成功后租约时间保持原始回调到达时间，排队不能延长租约或复活超时流。断连、停流、PTT及信用仍由原核心状态机控制。

频谱默认为关闭。关闭跳过PCM分析窗口维护、复制、FFT及柱/峰步进；重新开启或切换流会丢弃旧窗口并重置显示分析状态。入口任务栈3KiB；录音、播放任务各4KiB，未根据主机测试推断真机栈余量。

建议在相同App、网络、音量和讲话素材下，分别在开始及结束查询两节，比较同一sid/stream及开机累计差值。记录正常结束方式和查询时刻，避免跨流混用或把`lock_waits`当作丢帧。

## App 接入示例（固件1.4.0）

Info仍为major1/minor1、formats=[2]、frame_samples=160、audio_bytes=100；无需调整已有ADPCM音频包。`audio.stats`是可选诊断扩展，不作为HELLO成功或正常通话的前置条件。

```json
{"v":1,"id":101,"sid":7,"op":"audio.stats","p":{"section":"rx"}}
{"v":1,"id":102,"sid":7,"op":"audio.stats","p":{"section":"playback"}}
```

请求经原Control分片传输，sid使用当前HELLO返回值。响应仍为`{"v":1,"id":101,"sid":7,"ok":true,"r":{...}}`，`r`即上表字段；省略section默认rx，未知section返回bad_message。相同id重试遵循原响应重放缓存，采集新快照必须使用新id。建议手动采样或约每秒查询，避免诊断本身形成控制流量压力。

此命令的数据来自实体固件音频任务。Web模拟器同步UI、频谱设置与核心音频合同，但不等效模拟ESP32任务锁/I2S耗时，未安装实体统计回调时返回unsupported_operation；旧固件未知操作可能返回bad_message，App应把这些视为可选诊断不可用，不能拒绝正常通话。
