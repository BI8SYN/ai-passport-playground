# RF Link BLE 1.2：Opus 实验模式与压力测试

> 历史合同/试验记录：当前固件已收敛为[仅IMA-ADPCM](adpcm-only.md)，不再支持BLE PCM或Opus。本文旧模式、回退和测试构建说明不用于当前版本。

2026-11-02：用户要求增加Opus比较设备压力。本模式为可选实验能力，保留[PCM 1.0](protocol-v1.md)和[IMA 1.1](adpcm-v1.1.md)。GATT、配对、身份、控制分片、PTT、资料同步及流生命周期共用原协议，不引入设备证书或网络身份。

## 1. 参数和协商

| 参数 | Opus实验值 |
| --- | --- |
| 协议 | major=1，minor=2，format=3 |
| 输入/输出PCM | 8000Hz、单声道、S16LE |
| 每包 | 160采样、20ms |
| 编码 | Opus VOIP，16000bps，CBR，complexity=0 |
| DTX / FEC / VBR | 全部关闭 |
| 原始Opus包 | 固定40字节，含Opus TOC |
| 完整BLE音频值 | 原16字节头＋40字节包，共56字节 |
| 应用层传输码率 | 22.4kbps，50包/秒，不含Flow/ATT/链路开销 |

设备Info仅在本地Opus适配层可用时声明`minor=2,formats=[1,2,3]`；本轮Web模拟器没有接入乐鑫C3编解码库，只声明`minor=1,formats=[1,2]`，不能用它验证Opus声音。源码中的原始包解析及生命周期主机测试不是Mac模拟器新增Opus能力。

新App读取Info后使用：

```json
{"v":1,"id":1,"sid":0,"op":"hello","p":{"major":1,"minor":2,"format":3,"write_max":244}}
```

成功结果`r`包含：

```json
{"major":1,"minor":2,"format":3,"rate":8000,"samples":160,"frame_ms":20,"audio_bytes":56,"value_max":244,"credit_window":32,"audio_ready":true}
```

Opus要求协商M≥56；minor<2、无Opus能力或未知格式拒绝。切换编码必须用递增的新请求id发HELLO，旧流和采样FIFO清除，不支持同流混编码。旧App继续申请PCM或IMA；不能自动把Opus包发给format=1/2会话。

## 2. 字节格式和App接入

音频头与此前相同：字节0 major=1，字节1 flags bit0 discontinuity，字节2 format=3，字节3 sample_count=160（0xA0），字节4/8/12开始分别为uint32 LE的sid/stream_id/seq。seq按20ms帧递增1。字节16–55是完整原始Opus包，**无Ogg、无WAV、无自定界长度前缀，也不额外添加OpusHead/OpusTags**。

包必须单声道且解码总时长正好20ms；设备先检查40字节长度、TOC、帧计数/分帧及填充边界，随后由实际解码器校验码流。外层header合法不表示内部声码流合法，解码失败结束当前流并计错误。不能通过截断、在尾部任意补零或简单复制网络包的方式凑40字节；必须由CBR编码器生成。

[opus-vectors.json](opus-vectors.json)提供从全新编码器生成的3个连续音频包，含原PCM、40字节Opus和56字节完整帧，可按顺序喂给全新解码器检查160采样输出。生成器版本记录在文件中；不同Opus实现/版本的编码结果和解码舍入不要求逐字节相同，互通应检查合法包、帧长与连续试听。

App为BLE单独创建Opus编码器/解码器，采样率8000、channel=1、VOIP、CBR16000、complexity0、FEC/DTX关闭。每160个PCM采样编码一次，必须检查返回40字节。收到56字节BLE包后，独立校验头并用当前BLE流的Opus解码器解出160采样，再交网络编码器。不复用网络编码器状态，不直接透传网络40ms/变码率或聚合包。

Opus为有状态编码，不能像IMA那样假定每包独立。新sid/stream重建实例；连续帧保留状态。本实验接收端在序号缺口或discontinuity后重置解码状态，缺失播放槽补零；可能产生短暂恢复失真，尚未增加PLC/FEC联调。不能每包置discontinuity或每包重新创建编解码器。

末尾不足160采样时正常结束可先补零编码；松键、断连、紧急stop直接丢弃不足帧及待发旧帧。实际声学延迟包含Opus算法延迟与现有网络/播放缓冲，不能只用20ms帧长声称总延迟20ms。

## 3. 信用和资源行为

20ms模式沿用IMA规则：初始信用0–32，exclusive上界；每20ms消费一帧，信用每推进2帧主动更新，任一活动流Flow周期100ms。60ms起播每stream仅建立一次；高水位超过6帧裁剪至最新3帧。发送端最多积压120ms，正常50包/秒，不能一次塞满32帧。300ms断流、500ms麦克风信用、3秒会话、60秒TX限制保持真实毫秒。

固件固定依赖`espressif/esp_audio_codec=2.4.0`的C3实现，编码/解码在音频工作任务内执行，不在BLE回调或核心状态锁内执行。半双工只保留一个方向的实例，切换方向或新流释放旧实例；停止后释放资源。接收队列保存编码包，播放时才解码。

初始工作任务栈为mic 16KiB、speaker 8KiB，是否足够必须真机测量。创建实例失败、编码输出长度异常或解码错误会结束匹配流并发`stream.ended(reason=audio_error)`；若创建后剩余堆小于8KiB，也主动关闭实例、记录资源失败。该保留值是实验门限，不保证过程中的峰值内存或任务栈安全。

App收到此类错误应停止该流，读取统计，允许用户以新HELLO选择IMA/PCM；不要无限自动重试Opus。启动/HELLO支持Opus不等于当前内存足够创建编解码器。

## 4. 压力统计接口

使用普通控制分片请求（每次查询用新的递增id，同id重试返回缓存快照）：

```json
{"v":1,"id":20,"sid":305419896,"op":"codec.get","p":{"detail":"timing"}}
```

`detail`默认timing，也可为memory。响应沿用`ok/r`，拆成两个视图避免超过512字节。未安装此能力的模拟器/旧固件可返回不支持错误。

| timing字段 | 含义 |
| --- | --- |
| enc_frames / dec_frames | 本次启动成功编/解码帧数 |
| enc_avg_us / dec_avg_us | 成功帧处理耗时平均值 |
| enc_max_us / dec_max_us | 处理最大耗时，含失败调用 |
| over20ms | 处理耗时超过20000微秒的调用数 |
| errors | 创建/处理/输出格式等错误累计 |
| alloc_fail | 分配失败或创建后触及8KiB保留门限累计 |
| open_max_us | 创建编解码器最大耗时，单独统计 |

耗时为设备单调时钟测得的**经过时间**，含调度影响，不是精确CPU利用率。`avg_us/20000`可用于比较每帧预算占比；首次延迟还要加创建耗时。解码重置耗时计入该次decode，创建不计入平均处理时间。

| memory字段 | 含义，单位均为字节，mode除外 |
| --- | --- |
| heap_free / heap_min | 当前空闲8bit堆、启动以来最低空闲8bit堆 |
| largest_free | 最大连续空闲块 |
| mic_stack / speaker_stack | 两个音频任务历史最小剩余栈，须在实际运行后读取 |
| heap_before_open / heap_after_open | 最近一次创建前/后的堆快照，不是永久占用或峰值 |
| mode | 0无实例、1编码、2解码 |

统计按启动累计，不因HELLO重置。串口每10秒健康日志也输出Opus帧数、平均/最大耗时、超预算、错误、分配失败及任务栈。停止/切换流后mode回0不表示统计被清零。

## 5. 建议测试顺序

1. 先用旧PCM/IMA模式确认UI、配对、PTT及原有声音回归。
2. 选择Opus，先只收听30秒，读取两份codec.get；确认dec_frames增加，errors/alloc_fail无增长，最大耗时及栈余量合理。
3. 按住PTT短说3–5秒再松开，检查enc_frames、是否触及内存门限和20ms预算，确认松开立即停止。
4. 通过后延长到5/10分钟，分别测RX/TX及快速切换、序号缺口、写队列背压。记录手机/App版本、固件ELF、堆最低值和原始统计。
5. 若明显失真、预算超限、内存门限或重启，先停止Opus，回IMA对照；不要把主机libopus成功当成C3压力通过。

初版仅实现与构建验证；后续独立真机压力测试见第6节，仍未完成真实App/BLE语音与音质验收。写入前必须重新核对SSH设备的双OTA分区与当前启动槽，不能使用旧factory的0x10000偏移。

## 6. 设备独立压力测试入口与实测

无需App，可构建专用启动自测版本：

```sh
./tools/dev build rf-link-handmic --benchmark
```

该版本先在UI/BLE初始化前用临时40KiB栈做纯codec测试，再在完整UI/BLE/音频驱动初始化后使用实际mic/speaker任务做测试。每阶段预热10帧、测200帧，目标20ms节拍；超预算时主动让出CPU避免追赶循环饿死idle/WDT。内存合成PCM和公开Opus包均不经过麦克风/扬声器，不播放声音。所有编解码实例关闭后才切阶段，早期阶段统计/序号水位清理，再开始完整环境阶段。

普通`./tools/dev build rf-link-handmic`显式关闭自测，不会每次开机执行这些循环。自测版每次重启都会重跑；设备验收后应恢复普通工作固件。

2026-11-02真机结果：隔离环境编码200帧平均8.530ms、最大11.462ms；完整环境编码器初始化失败，未执行编码。完整环境解码两轮各200帧均成功，平均2.225/3.226ms、最大3.922/4.017ms。编码创建新增堆约24640字节、解码18452字节；完整环境仅约27932字节空闲、最大连续块19456字节，解码时最低空闲8272字节。当前主要限制为内存预算/连续空间，不可把隔离编码时间当作完整业务TX通过。

乐鑫编码器此次将内部`-7`初始化失败映射为外层通用错误`-1`，因此`errors`增加而`alloc_fail`可能仍为0；不能仅据后者判断内存充足。详细原始日志、栈余量和最终恢复镜像见[真机测试记录](../../development/rf-link-opus-device-benchmark-2026-11-02.md)。当前设备已恢复此前ADPCM版，未完成Opus实际BLE/App语音验收。
