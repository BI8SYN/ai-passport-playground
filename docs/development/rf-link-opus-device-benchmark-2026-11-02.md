# RF Link Opus 真机独立压力测试（2026-11-02）

用户要求直接在设备上测试编解码，不需要连接App。按本次授权，通过SSH至`liyongsheng@10.11.26.88`，在`/dev/cu.usbmodem11101`执行两轮静默测试。芯片ESP32-C3 rev1.1、8MB，MAC`4c:11:ae:2f:e7:a8`。均重新核对分区与有效OTA状态，仅写当前ota_0的0x20000，未备份、未全片擦除，未写NVS/otadata/分区表/引导程序/eFuse。

## 方法与范围

- 固定8kHz、单声道、160采样/20ms、16kbps CBR、VOIP、complexity=0，DTX/FEC/VBR关闭，乐鑫esp_audio_codec 2.4.0。
- 内存合成三角混合波形供编码，公开3个连续Opus包循环供解码，不采集实际麦克风语音或播放声音。每方向预热10帧、测200帧，约4.2秒；超出20ms时让出CPU，不持续追赶旧deadline。
- 隔离环境：启动早期、UI/BLE/音频驱动未初始化，临时任务栈40KiB。用于区分纯codec计算和完整应用资源限制。
- 完整环境：UI、BLE广播和音频驱动均初始化，在实际mic 16KiB/speaker 8KiB任务内运行。没有App连接/实际BLE语音流，不测手机调度、业务并发或声学延迟。
- 表中avg/max为包裹整个适配调用的单调时钟经过时间，包含调度影响；首个实例创建在预热期，不计入200帧均值。它不是精确CPU利用率。

结论：在此次合成短测中，隔离编码计算能落入20ms预算，完整环境主要受RAM预算/连续空间限制。24640字节编码器占用加入当前27932字节空闲堆后仅剩3292字节，亦低于8KiB保留门限；当前最大连续块也小于该总占用。不能仅提高编码任务优先级解决初始化失败。隔离调用链已用约16KiB栈，后续若让完整编码运行，需同时重新核对任务栈预算。

完整解码此时有计算余量，但最低空闲堆只约8KiB；连接手机后的BLE分配、控制报文和持续语音并未覆盖。不能据本记录宣称Opus全功能或长期稳定通过。`alloc_fail=0`也不代表无内存问题：此次乐鑫编码器把内部-7映射为通用-1，记录到errors，需结合串口初始化日志判断。
